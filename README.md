# 编校工具箱 Proofreader's Toolbox

一个本地运行的编校辅助工具集，含四个工具：

| 工具 | 页面 | 说明 |
| --- | --- | --- |
| **通用规范汉字表查询** | `/` | 输入一个汉字，查编号、级别与繁体/异体字（**纯静态**，双击即可用） |
| **GB/T 7714—2025 参考文献规则速查** | `/rules.html` | 标准条文、表格与示例的完整速查页 |
| **CY/T 266—2023 编校质量差错速查** | `/cyt266.html` | 标准条文与三张差错表的完整速查页 |
| **CY/T 121—2015 学术出版规范 注释速查** | `/cyt121.html` | 标准条文、两个附录的完整速查页 |

四页顶部共用一条品牌区「编校工具箱 Proofreader's Toolbox」，导航以短标签列出四个工具（汉字表查询 / GB/T 7714—2025 / CY/T 266—2023 / CY/T 121—2015），可直接跳转。

## 工具一：通用规范汉字表查询


输入一个汉字，查出它在《通用规范汉字表》（2013）中的**编号**与**所在级别**，并显示对应的繁体字、异体字；支持繁体字、异体字反查。

全表 8105 字：一级 3500 字（编号 1–3500）、二级 3000 字（3501–6500）、三级 1605 字（6501–8105）。

## 快速开始

**直接打开 `public/index.html` 即可**（双击就行）。页面是纯静态的，查询、繁体/异体反查、分级统计与字表浏览全部在浏览器内完成，不需要任何服务端。

也可以起一个本地静态服务器（便于局域网访问或避免个别浏览器对 `file://` 的限制）：

```bash
npx serve public          # 或任意静态服务器
```

发布到网上只需一行构建命令：

```bash
npm run build             # 等价于 node scripts/build-site.js
```

它会先把字表数据写入 `public/data/api-data.js`，再把 `public/` 整体复制到 `docs/`（GitHub Pages 用）。然后把 `docs/` 或 `public/` 交给任意静态托管即可。

无需 `npm install`：项目零依赖，只用 Node 内置模块（要求 Node ≥ 18，实测 v24；仅构建脚本需要 Node，浏览页面不需要）。

## 使用说明

- 输入框里输入或粘贴一个字，回车（或点击「查询」）即可。输入时会实时出结果。
- 结果给出：**编号**、**级别**（一级/二级/三级字表）、Unicode 码位、全表位置，以及该字的繁体字、异体字。
- **反查**：输入繁体字或异体字同样能查到对应的规范字，结果上会标注「由繁体字反查」「由异体字反查」。例如输入「樹」得到规范字「树」的编号 1439、一级。
- **浏览**：页面下方可按级别切换浏览全表，点击任意字即查询该字。
- **最近查询**：保留最近 12 个查询，存在浏览器本地（localStorage），可一键清空。
- 不在 8105 字之内的字符会明确提示「未收录」并给出其码位（如 `囧`、`龘`、`〇`、`𠮷` 均不在表内）。

## 字体统一说明

**字体已自托管，读者无需安装霞鹜文楷**。站点内置该字体的裁剪子集（`public/fonts/`，两档共约 5 MB）：

| 文件 | 字重 | 说明 |
| --- | --- | --- |
| `lxgw-wenkai-400.woff2` | 400 | 正文常规 |
| `lxgw-wenkai-500.woff2` | 500–700 | 中粗：标题、加粗、术语名等（用真字体而非浏览器合成加粗） |

- 子集**按站点实际用字裁剪**：全部 8105 字 + 繁体/异体 + 页面文字，共约 11000 字，体积从原字体 24 MB 降到 2.5 MB。
- 通过 `unicode-range: U+0000-10FFFF` 覆盖全部平面，**扩展 B/C/D 区生僻字（如 `鿍 鿎 鿏 𬉼`）也在覆盖内**——这是宋体、楷体等系统字体做不到的。
- 浏览器**按需下载**：只加载当前页面实际用到的那一档，且仅首次访问时下载，之后走缓存。
- 重新生成（需本机已安装霞鹜文楷，脚本会从系统字体目录读取源文件）：

```bash
python scripts/build-fonts.py
```

- 若字体文件缺失或加载失败，会按下面的字体栈自动回退到系统字体，页面不会报错。


界面上所有汉字（输入框、结果卡片大字、繁体/异体字、字表浏览、级别统计）与界面文字共用**同一套字体**，避免同一个字在不同位置、或字与字之间显示成不同字体。

CSS 变量 `--han` 统一管理，优先使用**霞鹜文楷**：

```css
--han: "LXGW WenKai", "LXGW WenKai Mono", "Microsoft YaHei", "微软雅黑",
       "PingFang SC", "Hiragino Sans GB", "Heiti SC", "Source Han Sans SC",
       "Noto Sans CJK SC", "WenQuanYi Micro Hei", sans-serif;
```

经实测（逐个字读取浏览器实际渲染所用的平台字体）：

| 字体 | 对本表 8105 字的覆盖 |
| --- | --- |
| **霞鹜文楷 LXGW WenKai** | **8105 / 8105，零回退** |
| 微软雅黑 Microsoft YaHei | 8105 / 8105，零回退 |
| 等线 DengXian | 8105 / 8105，零回退 |
| 宋体 SimSun | 缺 `鿍 鿎 鿏` 3 字 |
| 楷体 KaiTi、黑体 SimHei | 缺 199 个扩展 B 区字，会回退成别的字体 |

几个注意点：

1. 霞鹜文楷在 CSS 中必须写英文内部名 **`LXGW WenKai`**；注册表里显示的中文名「霞鹜文楷」浏览器并不识别（写了等于没写）。
2. 早期版本用楷体，导致全表 199 个扩展 B 区生僻字（如 `𬉼 𠳐 𠙶 𬣙`）回退到别的字体，同时结果卡片与字格用的也不是一套字体——这正是"字体不一致"的成因，现已修正。
3. 若本机未安装霞鹜文楷，会自动回退到微软雅黑/等线等同样全覆盖的字体，**复制页面时两条字体栈可一起带走**；如需绝对统一，任选表中一款全覆盖字体即可。

### 约定：全站不使用等宽字体

**不用 `ui-monospace` / `Consolas` / `Menlo` 等等宽字体**，原因是被实测验证过的字形问题：

- Consolas 的 `U+2014` `—` 只有约 **0.5 字符宽**，于是规范写法 `——`（两个 U+2014，应为 2 个汉字宽）在页面上只占约 **1.06 个汉字宽**，看起来明显偏短。
- 霞鹜文楷下 `——` 实测为 **2.00 个汉字宽**，与规范写法一致。

需要数字对齐时用 `font-variant-numeric: tabular-nums` 解决，**不要换字体**。

> 页面里 `.mono` / `code` 这些类名保留（HTML 中已大量引用），但它们的 `font-family` 同样指向 `--han`，不引入等宽字体。

### 约定：脚注角标作上标

规范里的**圈码序号**（`①` `②` `③` …，用于脚注方式的参考文献标注）应作**上标**显示，不能与正文同大。`rules.html` 中统一用：

```html
<sup class="fn">①</sup>
```

样式用 `position: relative` 位移而非改 `vertical-align`，避免撑高行距：

```css
.fn, sup.fn { position: relative; top: -0.42em; font-size: .62em; line-height: 0; vertical-align: baseline; }
```

例外：**讲字符本身的说明文字**（如"序号可由计算机自动生成圈码（①②③④）"）保持原大小，以便看清字符。

## 数据来源与整理说明

- **分级字表**（字序即编号顺序）：[shengdoushi/common-standard-chinese-characters-table](https://github.com/shengdoushi/common-standard-chinese-characters-table)
- **附表一《规范字与繁体字、异体字对照表》**：[lqfeng/ChineseCharacters](https://github.com/lqfeng/ChineseCharacters)

`node scripts/fetch-data.js` 会重新下载并生成数据，过程中校验：总字数 8105、各级字数 3500/3000/1605、无重复汉字、对照表编号与分级字表逐行一致。

对照表整理上的两点取舍（脚本内有注释）：

1. 对照表第二栏（繁体）与第三栏（异体）在只含**单个字**时，是该规范字对应的繁体字、异体字，可靠，照原样收录。
2. 两栏出现**多个字并用竖线分隔**时表示「真异体字组」（96 行）。实测其组内顺序与位置并非严格配对（如 `里 → (里|裡)` 与已有的 `裏/裡` 标注冲突），因此只逐行收录，不推导组内配对，避免生成错误映射。另有 2 行异体栏含多字连写（如 `乃 → [廼迺]`），按源数据原样保留为一组。

依此整理后：2161 字带繁体字、789 字带异体字。
